# v2.1.2 — Broad General Reasoning Transfer

## Why this exists

v2.1.1 fixed the catastrophic v2.1 overwrite problem, but its selected Stage B1 checkpoint was only an incremental win: the strong original query-aware procedure path stayed at about 0.953, supported correctness rose slightly, faithfulness slipped slightly, abstention fell, and the new collision challenge improved only to roughly 0.023. The important research lesson is that a narrowly targeted procedure curriculum may be too local to create a materially stronger student.

v2.1.2 therefore changes the question from:

> Can we repair one procedural failure mode?

into:

> Can a broad curriculum of reusable reasoning operations strengthen the student in a way that transfers to factual/RAG/procedural behavior while preserving the abilities it already has?

This is **not** a general-world-knowledge memorization phase. The student remains a short-response, RAG-oriented model. General reasoning examples contain the needed facts in the prompt and train transferable operations rather than encyclopedic facts.

## Dataset

`data/phase_9_student_distillation/general_reasoning_v212/`

- 13,200 deterministic canonical examples
- 33 reasoning families
- 10,560 TRAIN
- 1,320 DEV
- 1,320 sealed TEST
- 12,000 answerable examples
- 1,200 insufficient-information/abstention examples
- 4,000 easy / 6,400 moderate / 2,800 hard

Families cover arithmetic, rates, ratios, percentages, dates, durations, ranking, min/max, smallest-sufficient capacity, threshold rules, AND/OR conditions, filter-then-rank, tie breaking, transitive comparisons, set intersection, schedule overlap, state transitions, prerequisites, entity tracking, two-hop relations, path cost comparison, sequences, parity, counterfactuals, diagnostic priority rules, table filtering, exception precedence, and insufficient-information reasoning.

Gold answers are generated by code. Verification metadata records the underlying operation and expected result, but **no chain-of-thought/rationale is placed in the assistant target**.

## Training curriculum

Candidate zero is always the exact input student/adapter. It is never discarded merely because a trained checkpoint exists.

### Stage A — broad reasoning core

- 4,800 balanced general-reasoning rows
- 160 optimizer steps
- LR 1e-5

Purpose: create a meaningful broad-reasoning update rather than another 60-step micro-repair.

### Stage B1 — generalization + preservation

- 6,000 rows
- 3,600 general reasoning (60%)
- 1,200 train-only original Phase 9 replay
- 1,200 train-only v2.1.1 replay
- 160 optimizer steps
- LR 7.5e-6

Purpose: consolidate reasoning while continually replaying grounded factual, procedural, abstention, conflict, and social behavior.

### Stage B2 — lower-rate continuation

- same mixed view
- 120 optimizer steps
- LR 5e-6

Purpose: provide one later checkpoint without assuming more training is automatically better.

The default total is 440 steps. A runner guard rejects LR above 3e-5 or total steps above 600 unless `-AllowAggressiveTraining` is explicitly supplied.

## Three DEV axes after every checkpoint

Each checkpoint is evaluated on:

1. Original Phase 9 DEV under `query_aware_v21` Real-RAG/Oracle-RAG.
2. v2.1.1 procedural challenge DEV under the same retrieval policy.
3. v2.1.2 direct general-reasoning DEV.

General reasoning reports:

- overall correctness;
- macro accuracy across all 33 families;
- hard-case correctness;
- abstention correctness;
- short usable output rate.

The selector treats general-reasoning improvement as the primary benefit, procedural challenge improvement as a secondary possible transfer gain, and original RAG/abstention/faithfulness/social regressions as preservation cost.

## Recommended first run

Use whichever student you want to treat as the experimental baseline. The safest scientific comparison is to start from the original strong query-aware student; starting from the v2.1.1 Stage B1 adapter is also supported and measures incremental gain from that checkpoint.

```powershell
.\scripts\phase_9_student_distillation\run_phase_9_general_reasoning_v212.ps1 `
  -StudentModel "C:\path\to\student_base_or_checkpoint" `
  -StudentAdapter "C:\path\to\input_adapter" `
  -RequireCuda
```

For a checkpoint with no adapter, omit `-StudentAdapter`.

Do **not** use `-RunSealedTest` on the first run. Review `GENERAL_REASONING_V212_SELECTION.md` first.

After one DEV-selected candidate is frozen:

```powershell
.\scripts\phase_9_student_distillation\run_phase_9_general_reasoning_v212.ps1 `
  -StudentModel "C:\path\to\student_base_or_checkpoint" `
  -StudentAdapter "C:\path\to\input_adapter" `
  -OutputRoot ".\artifacts\phase_9_general_reasoning_v212_YYYYMMDD_HHMMSS" `
  -ReuseExisting `
  -RunSealedTest `
  -RequireCuda
```

Sealed TEST evaluates the DEV-selected candidate once on original Phase 9 TEST, v2.1.1 procedural TEST, and v2.1.2 general-reasoning TEST. It does not train or recalibrate.

## Interpretation

A useful v2.1.2 result is not required to increase every score. The key research question is whether broad reasoning gains are large and repeatable enough to outweigh measured preservation costs. If not, the input student is intentionally retained.
