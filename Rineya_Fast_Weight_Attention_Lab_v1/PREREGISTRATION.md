# Preregistration — Supa-A1.1 Fast Weight Attention v1

Written **before** P2 matched inference. Amendments after this file is committed
must be appended, not silently rewritten.

Classification: `EXPLORATORY_NOT_CONFIRMATORY`.

## Hypotheses

H0 (null). Adding a bounded FALCON-2 pathway to frozen Supa-A1.1 does not
improve long-context retrieval or positional robustness beyond a
parameter-matched static control.

H1 (Q1). Arm C improves exact-match retrieval over Arm A on the unsealed
position-conditioned suite.

H2 (Q2). Arm C improves over Arm B. Failure of H2 (B ≈ C or B > C) is evidence
that any gain is from extra parameters, not recurrent fast-memory.

H3 (Q3). Arm C reduces the middle-vs-edge accuracy gap relative to Arm A at
matched context length.

H4 (Q4). Arm D improves over Arm C. This is a **Rineya extension**, not a FALCON
paper claim.

H5 (Q5). Recurrent state bytes stay bounded in sequence length while KV-cache
bytes grow. No efficiency claim without measured peak VRAM and tokens/sec.

## Arms and training contract

- Backbone: Supa-A1.1, frozen, loaded float16, `trust_remote_code=True`.
- Trainable: FWA projections, feature norms, plasticity/forgetting, merge gate,
  and (Arm D only) the significance gate.
- P1: one seed (11), Arm C, layer `[14]`, rank 16, unsealed data only.
- P2: seeds `{11, 22, 33}`, arms A/B/C/D, default layers `[14]` unless P1
  forces a documented redesign.
- Arm E is not run in this registration.

## Data

Unsealed TRAIN/DEV generated by this lab (`scripts/build_cc0_subset.py`).

If the official CC0 builder and unsealed shards are present and complete, the
builder prefers that source and records hashes. If they are absent (the CC0
tree is gitignored and was not present in this worktree at isolation), the lab
builds a **documented synthetic unsealed** retrieval mix with the same schema
fields (`messages`, `metadata.context_stratum`, `metadata.evidence_position`).

Never train on TEST, TEST2, sealed_eval, showcase64, or PSA sealed examples.

## Metrics

- Strict exact match and trimmed exact match.
- Position-conditioned accuracy at relative positions
  `{0.05, 0.10, 0.25, 0.50, 0.75, 0.90, 0.95}`.
- Middle-vs-edge gap: mean({0.25, 0.50, 0.75}) − mean({0.05, 0.10, 0.90, 0.95}).
- Length degradation across 512 / 1024 / 2048 / 4096 (skip any length that
  exceeds measured VRAM).
- Abstention rate (`UNKNOWN`) and malformed-output rate.
- Interference battery A–G: retained / overwritten / blended / wrong.
- Resource: trainable params, recurrent state bytes, KV-cache bytes, peak VRAM,
  tokens/sec, TTFT.

## Decision rule (after P2)

| Label | Rule |
|---|---|
| GO | C beats A **and** C beats B across seeds, **or** D beats C, with acceptable resource cost |
| WEAK GO | Clear positional or interference signal; aggregate accuracy neutral |
| REDESIGN | Fast memory is active but interference dominates |
| NO-GO | B ≈ C or B > C; no position benefit; instability; or inference overhead dominates |

A negative result remains committed.

## Claim limits

- Inference-time **fast-weight state** is not permanent parameter fine-tuning.
- It is not lifelong learning unless a later study specifically shows retention
  across sessions with saved state.
- Showcase64 / published family numbers are out of scope.

## Compute parity

All P2 arms share seed, data order, max steps, sequence length, decode settings,
and evaluation items. Arm A is eval-only (no training).

# Amendment 1 — P2b (appended; nothing above was altered)

Written **after** the P2 post-mortem in `reports/MECHANISM_DIAGNOSTIC.md` and
**before** any P2b arm was trained or evaluated.

## Why P2 is withdrawn rather than believed

The P2 NO-GO is withdrawn as unsupported. Measurement, not opinion:

- the fast memory's retention half-life was **87.5 tokens** with total overwrite
  on key collision (`beta = 1.0`, the NLMS deadbeat point), against contexts of
  ~990 tokens — it could not carry any scored fact to its query;
- arms B/C/D nevertheless differed mechanically (contribution to the attention
  output 0.12 % / 1.41 % / 3.22 %; up to 3.4 logits, 0.25 nats KL), so the
  identical predictions were a property of a saturated eval, not of the pathway;
- the eval was one repeated filler sentence, a 10-word answer space, and one
  item per (length, position) cell — a paired exact test would have needed 6 of
  14 items to flip to reach p < 0.05;
- `run_experiment.py` hardcoded `lengths = [256, 512]` over the config's
  `[512, 1024, 2048, 4096]`, and `train.py` hardcoded `init_alpha = 0.05` over
  the config's `0.0`.

H1–H5 were not tested. P2b tests them.

## What changes, and why each change is forced

| Change | Reason |
|---|---|
| Token-exact 1K / 2K / 4K contexts, verified per item | P2's "512" items were 990 tokens; no length was what it claimed |
| Real CC0 filler from the already-committed `data/unsealed/` shard | P2's filler was one sentence repeated 21-42x, making the needle the only non-duplicated sentence |
| 48 decoy facts of identical surface form, confusable keys from one numeric band | removes both "spot the odd sentence" and literal key matching |
| 552-code single-token answer space, 32 candidates per item | P2's answer space was 10 colour words |
| Candidate-argmax scoring in one forward pass | removes the malformed-output artifact that produced P2's only arm-A "miss" (`color slate`); also makes long-context eval affordable given the wrapper's KV-cache refusal |
| n_per_cell = 8 (168 position items), 8 per interference category (56 items) | P2 had 1 per cell and could not reach significance |
| Long-horizon init, **matched across B/C/D**: `beta_raw = -1.1`, `lambda_raw = -5.9` | gives `beta = 0.499` (partial write, not deadbeat) and half-life ~8100 tokens, so the memory can span the evaluated context |
| Training on a long-context split disjoint from eval, not front-truncated | P2 trained on the 10-colour synthetic corpus and front-truncated long rows, destroying the needle |
| 100 optimizer steps at lr 1e-3 (Adam movement bound 0.1 vs P2's 0.0024) | in P2 alpha was still ramping at 67-83 % of its maximum rate when training stopped |
| `init_alpha` read from the caller and recorded in the manifest | P2's configs did not describe P2's run |

## New arm

**Arm C-short** — arm C with the *original* P1/P2 short-horizon init
(`beta_raw = 0.0`, `lambda_raw = -2.0`), one seed. This makes the horizon change
a measured ablation rather than an assumption. Predicted: C-short ~= arm B.

## Hypotheses (unchanged in substance, now testable)

H1 (Q1) C > A. H2 (Q2) C > B. H3 (Q3) C narrows the middle-vs-edge gap.
H4 (Q4) D > C. H5 (Q5) bounded state vs growing KV cache.

Added: **H6.** C (long horizon) > C-short. If H6 fails, the retention horizon is
not the binding constraint and the P2 diagnosis was wrong.

## Statistics, fixed in advance

- Primary metric: strict candidate-argmax exact match on the position suite.
- Primary contrasts: C-A, C-B, D-C, C vs C-short, each by **paired two-sided
  exact McNemar** on matched item ids, reported per seed.
- Wilson 95 % intervals on every reported rate.
- Middle = {0.25, 0.50, 0.75}; edge = {0.05, 0.10, 0.90, 0.95}.
- Seeds {11, 22}. Seed 33 only if wall-clock allows; its absence is reported.
- No metric, length, or arm may be added after seeing P2b results. Anything
  added later is labelled exploratory.

## Decision rule (supersedes the P2 rule for P2b only)

| Label | Rule |
|---|---|
| GO | C > B at p < 0.05 in both seeds, or D > C at p < 0.05 in both seeds, with acceptable resource cost |
| WEAK GO | consistent directional C > B in both seeds without significance, or a position-restricted effect |
| REDESIGN | fast memory measurably active and interference-dominated (interference battery worse than A while position improves) |
| NO-GO | B >= C, no positional benefit, instability, or overhead dominates |

A NO-GO here means something, because the mechanism is measured live, the
horizon spans the context, and the suite is off ceiling.

## Hardware envelope (measured, not assumed)

RTX 4070 Laptop, 8188 MiB. 1K/2K/4K run natively (peak 3.64 GiB at 4K). 8K only
via host-memory spill at ~6x slowdown. **16K OOMs and is not evaluated.** The
brief's 8K/16K tiers are therefore reported as not measurable on this hardware
rather than silently dropped.

## Sealing (unchanged)

CC0 `sealed_eval/`, Invisible-Limit TEST/TEST2, showcase64 / stability192, and
PSA `data/sealed/` remain closed. P2b reads only `data/unsealed/` (already
committed with hashes) and lab-generated rows. The PSA benchmark generator was
inspected but **not** invoked, because it writes into another lab's tree and
owns a `sealed` split.

# Amendment 2 — suite difficulty, fixed before any P2b arm was trained

Amendment 1's table says "48 decoy facts of identical surface form" and does not
mention indirection. The run uses **24 decoys and two-hop binding**. Recording the
change here rather than editing Amendment 1, and recording *why*, because a
preregistration that quietly matches the run after the fact is worth nothing.

## What changed

| Amendment 1 | Actual run |
|---|---|
| 48 decoys | `n_decoys: 24` |
| one hop (`vault -> code`) | two hops (`vault -> unit -> code`), `hops: 2` |

## Why, with the calibration that forced it

Amendment 1 was written before the difficulty calibration had been run. When it
was run — on **arm A only**, with no adapter loaded and no arm compared, so it
cannot bias the A/B/C/D contrast — the one-hop design turned out to still be at
ceiling:

| Design | length | decoys | arm A exact | arm A at position 0.05 |
|---|---:|---:|---:|---:|
| one hop, random keys | 1024 | 24 | 0.833 | 0.75 |
| one hop, confusable keys | 1024 | 24 | 0.889 | 1.00 |
| one hop, confusable keys | 2048 | 24 | 0.889 | 0.833 |
| one hop, confusable keys | 2048 | 48 | 0.889 | 0.833 |
| **two hop, confusable keys** | **2048** | **24** | **0.778** | **0.333** |
| two hop, confusable keys | 2048 | 48 | 0.889 | 0.833 |

A single `vault -> code` lookup stays near ceiling even with 48 confusable
decoys, because it is a surface match attention can do directly. More decoys did
not help: 48 was *easier* than 24 in both one- and two-hop settings, since more
fact sentences displace filler and make the pattern more salient. Two-hop
binding at 24 decoys is the only configuration that put the frozen backbone off
ceiling (0.778) with a real primacy deficit (0.333 at relative position 0.05).

The purpose of Amendment 1 was a suite that can discriminate. Keeping "48
decoys, one hop" would have reproduced the exact defect Amendment 1 exists to
remove.

## Timing, so this is checkable

Calibration ran, the config changed, and both were committed
(`51311b6 Calibrate P2b off ceiling`) **before** the P2b run started
(`07:15:22`, 2026-09-02) and therefore before any arm was trained. No P2b
outcome had been observed. Nothing else in Amendment 1 changes: the arms,
horizons, statistics, seeds and decision rule stand as written.

# Amendment 3 — design sensitivity, computed before any P2b result exists

Written while P2b is still training (3 of 7 arms, zero evaluations). No outcome
has been observed. This fixes in advance what the design *can* and *cannot*
detect, so that a null result is interpretable rather than being read as "no
effect" — which is precisely the error the withdrawn P2 conclusion made.

Paired two-sided exact McNemar, alpha = 0.05, n = 168 paired position items.
Significance depends on the DISCORDANT pairs only, not on n.

## Smallest detectable win

| Discordant pairs, all favouring one arm | p |
|---:|---:|
| 4 | 0.125 |
| 5 | 0.0625 |
| **6** | **0.0312 — first significant** |
| 8 | 0.0078 |

Six clean wins and zero losses (a 3.6 pp net gap) is detectable. That is a
sensitive design *when the advantage is consistent*.

## Where the design goes blind

| C wins / B wins | net gap | p |
|---|---:|---:|
| 12 / 3 | 5.4 pp | 0.035 — significant |
| 14 / 5 | 5.4 pp | 0.064 |
| 20 / 10 | 6.0 pp | 0.099 |
| 24 / 13 | 6.5 pp | 0.099 |
| 30 / 18 | 7.1 pp | 0.111 — **not** significant |

The same net gap can be significant or not depending on how much both arms
disagree with each other. A **+7.1 pp advantage for arm C buried in high
discordance would not reach p < 0.05 here.**

## Therefore, agreed in advance

- A null on C−B means **"no consistent per-item advantage at this sample size"**.
  It does **not** mean "no effect", and must not be written up as one.
- Every contrast is reported with its discordant counts (`b_better`, `a_better`),
  never with the p-value alone, so a reader can see which regime it fell in.
- If a contrast lands in the blind region — a net gap of roughly 5 pp or more
  with p > 0.05 — that is reported as **underpowered**, and the honest next step
  is more items or more seeds, not a NO-GO.
- The GO rule in Amendment 1 is unchanged. What changes is that a failure to meet
  it will be labelled by regime: *no effect*, *underpowered*, or *effect against*.

# Amendment 4 — a falsifiable prediction for arm C-short, logged before its result

Written while arm C-short is training and before its manifest exists. Six of
seven training runs are complete; no evaluation has run.

Amendment 1's central justification for P2b is the claim that the P1/P2 retention
horizon (half-life 87.5 tokens, with `beta = 1.0` fully overwriting along the
written key direction) was too short to carry a fact across the context. That
claim is load-bearing: it is why the horizon was changed, and therefore why any
arm-C win in P2b is not simply a consequence of my having picked a friendlier
setting. It deserves to be exposed to falsification rather than assumed.

Arm C-short is arm C with the original short horizon, everything else identical.

## The prediction

Observed so far, at the long horizon:

| Arm | alpha (from 0.05) | final loss |
|---|---:|---:|
| B (static, no state carry) | 0.099 – 0.101 | ~0.003 |
| C (recurrent, long horizon) | 0.070 | 0.0002 – 0.0004 |
| D (gated, long horizon) | 0.068 – 0.070 | 0.0002 – 0.0004 |

**Predicted: arm C-short resembles arm B, not arm C** — a larger merge gate
(alpha nearer 0.10 than 0.070) and a final training loss nearer 0.003 than
0.0003. Reasoning: with an 87.5-token half-life the recurrent state cannot carry
information across a 1024-token training context, so arm C-short should be
forced to behave like a per-token transform, which is exactly what arm B is.

## What each outcome means

- **C-short looks like B** — consistent with the diagnosis. The horizon is the
  binding constraint, and changing it was justified rather than convenient.
- **C-short looks like C** — the diagnosis is **wrong**. The retention horizon is
  not what separated the arms, the stated rationale for Amendment 1 does not
  hold, and any arm-C advantage in P2b needs a different explanation. This would
  be recorded as a failed prediction of mine, not quietly dropped.
- **C-short beats C** — the long-horizon init is actively harmful and the change
  was a mistake.

Training-loss behaviour is held-in and is *not* the test of H6; the held-out
C vs C-short contrast is. This amendment fixes the prediction so that whichever
way it falls, it cannot be reinterpreted after the fact.

# Amendment 5 — analysis focus, fixed after the arm-A baseline and before any contrast

Arm A (unmodified Supa-A1.1) has been scored on the P2b suite. **No treatment arm
has been scored and no contrast has been computed.** Recording three properties of
the baseline now, because each one changes how a contrast should be read, and
deciding that after seeing the contrasts would be choosing the analysis to fit
the answer.

Arm A, n = 168, exact 0.8214 [0.757, 0.872], abstention rate 0.000:

| position | 0.05 | 0.10 | 0.25 | 0.50 | 0.75 | 0.90 | 0.95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| exact | **0.417** | 0.708 | 0.792 | 0.917 | 0.958 | 1.000 | 0.958 |

| length | 1024 | 2048 | 4096 |
|---|---:|---:|---:|
| exact | 0.857 | 0.786 | 0.821 |

## 1. The interference battery is at ceiling and cannot discriminate

Arm A scores **55/56 (0.982)** — every category 8/8 except B at 7/8.

The position suite was calibrated off ceiling; the interference battery never
was. That is my omission, and it reproduces the exact defect P2b exists to
remove, on the interference dimension. With one item of headroom no arm can
separate from another.

**Agreed now: any interference result in P2b is uninformative and will be
reported as such.** It is not evidence of "no interference difference"; the
instrument cannot see one. Section 14 of the brief is therefore *not* answered by
this run. Rebuilding the battery harder is follow-up work, not a P2b patch.

## 2. The middle-vs-edge metric presupposes the wrong deficit

H3 was worded as "C reduces the middle-vs-edge gap", assuming a
lost-in-the-middle deficit. This backbone does not have one. Accuracy rises
monotonically with position, 0.417 at 0.05 to 1.000 at 0.90: a **primacy
deficit**, i.e. a recency gradient. Middle beats edge (+0.118) only because the
edge average pools the very weak 0.05/0.10 cells with the perfect 0.90/0.95 ones.

"Reducing the middle-edge gap" is therefore not a meaningful goal here — it could
be achieved by making the middle *worse*. The metric is retained for continuity
but is demoted.

**Primary positional quantity, fixed now: exact match at the early positions
{0.05, 0.10}**, where arm A scores 0.417 and 0.708 and there is real headroom.
That is where a memory that carries early evidence forward would show up.
Middle-edge gap is still reported, with its sign, as a secondary number.

## 3. There is no length degradation to explain

0.857 / 0.786 / 0.821 across 1024 / 2048 / 4096 is flat within the interval.
Difficulty in this suite lives on the **position** axis, not the length axis.
Accuracy-vs-length is still reported, but a null there is expected and carries
little information, and "length robustness" claims should not be made from it.

## Unchanged

Arms, horizons, seeds, the paired exact McNemar test, Wilson intervals,
Amendment 3's sensitivity limits and Amendment 1's GO rule all stand. This
amendment changes which numbers are foregrounded, not how any of them is
computed.

# Amendment 6 — a calibration error of mine, recorded before the C-B contrast exists

Arms A and B are scored. **Arm C has not been scored and no contrast has been
computed.** Recording this now because it bounds what the headline contrast can
show, and noticing it after the fact would look like excuse-making.

## What arm B did

| position | 0.05 | 0.10 | 0.25 | 0.50 | 0.75 | 0.90 | 0.95 | total |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A (frozen) | 0.417 | 0.708 | 0.792 | 0.917 | 0.958 | 1.000 | 0.958 | 138/168 |
| B (static control, seed 11) | 0.917 | 0.792 | 0.958 | 1.000 | 1.000 | 1.000 | 0.958 | 159/168 |

The parameter-matched **static** control — 524,593 trained parameters, no
recurrent state carry — recovers most of the primacy deficit on its own
(0.417 -> 0.917 at position 0.05; early positions 27/48 -> 41/48).

## The calibration error

I calibrated the suite so that **arm A** was off ceiling (0.821). But arm A is
not the comparison that matters. The preregistered headline contrast is
**C vs B**, and B is a *trained* arm. Calibrating difficulty against the
untrained baseline set the wrong reference: training lifts the control to
0.946, leaving **9 items** of headroom for arm C.

This is the same mistake as the interference battery in Amendment 5, in a subtler
form: I checked the instrument against the wrong arm.

## Consequences, agreed now

- By Amendment 3, arm C needs **6 clean discordant wins** for p < 0.05. With only
  9 of B's items left wrong, C must fix at least two thirds of B's residual
  errors and break none. That is a demanding bar, and **failing it is weak
  evidence**, not strong evidence of no effect.
- A C-B null in this run must therefore be reported as **compressed-range and
  underpowered for the true effect size**, not as "recurrence adds nothing".
- The correct fix is a suite calibrated against a *trained* control, not against
  the frozen backbone. That is follow-up work; it cannot be retrofitted to this
  run without invalidating the preregistration.
- **What arm B already establishes stands regardless of arm C**: on this task,
  most of the positional gain needs only extra parameters applied per token, not
  memory. That is a genuine finding and it favours the H2 null.

Nothing about the test, the arms or the GO rule changes.

# Amendment 7 — correcting Amendment 5: a ceiling blocks gains, not losses

Amendment 5 said "any interference result in P2b is uninformative and will be
reported as such". **That was too strong and I am correcting it before relying
on it.**

A ceiling limits the detection of **improvement**. It does not limit the
detection of **degradation**. With arms A and B at 55/56 there is one item of
headroom above and fifty-five items of room below. So:

- An interference **tie** between arms remains uninformative — that part of
  Amendment 5 stands.
- An interference **drop** is a real, detectable signal, and the battery is if
  anything well suited to catching one.

This matters because arm C (seed 11) scores 50/56 against 55/56 for both A and
B: five paired discordant items, **all five against arm C**, p = 0.0625, with the
loss concentrated in category **F** (decisive fact early, twelve distractors
after), where C scores 4/8 against 8/8 for A and B.

That is exactly the failure mode a bounded recurrent state predicts: later writes
overwriting an early fact. Amendment 5's blanket wording would have let a real
finding be discarded as instrument noise. It is retained as a finding, with the
caveat that five discordant pairs give p = 0.0625 and fall just short of the
preregistered 0.05 threshold, and that seed 22 has not been scored.

No change to any test, arm, or decision rule.
