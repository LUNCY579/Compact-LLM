## Dataset interventions

Four generative primitives share a typed planning interface: R reference binding, U state updates, S constrained selection, P precedence ordering. Build atomic banks plus actual dependent pipelines, not independent questions pasted together. Include all six pairs, four triples and the four-skill pipeline in exposed evaluation. Only RU/US/SP bridges are train-eligible; other pairs and every triple/four-way signature are withheld from training, warm-start and calibration. All descendants of one world share a split and parent ID. Each active stage has a changed-stage test where a formerly valid answer becomes invalid and an independently solved alternative succeeds. These show local dependency, not absence of shortcuts.

Separate preservation rehearsal from held-out source-correct guard banks. New legacy-family instances are excluded against the provided v1 corpus by exact normalized public-instance identity; semantic equivalence and all other historical corpora remain unqualified. Answerability twins differ only in a selection target inside the attainable numeric range: one feasible, one provably infeasible. UNKNOWN and false abstention remain separate endpoints. A dataset can support rehearsal and measure forgetting; it cannot promise no forgetting or identify skills already held by a model without a baseline run.

## Registered comparisons, not a native launch

First select ONE new generator pair and bind an immutable source/tokenizer/runtime/trainable inventory. Train independent A and B from the SAME anchor, using GRPO versus MaxRL under equal tuning allowances and explicit token/compute ceilings. Freeze individual skill-positive-controls before interpreting composition. Evaluate theta0 + alpha_A*delta_A + alpha_B*delta_B with independent development-selected coefficients. Preserve the unmodified delta_A control at the same alpha_A. Never silently normalize the sum. Record per-delta norm, total norm, cross term, parameter scope, exact anchor and deployed cast. Orthogonal projection is an optional separately labelled direction-changing control, not a proven method and not synonymous with module-specific data.

Then compare A->B with versus without replay, interleaved multi-task training, and explicit bridge adaptation as SEPARATE factors. A combined skill task seen in bridge training is not zero-shot composition. Third/fourth skills are staged expansions, not 2**4 native runs implicitly authorized here. Replay can be binary MaxRL (possibly zero signal on mastered rows) or a separate anchor-KL/SFT regularizer; do not claim all-success replay guarantees preservation or mix a shaped reward into the binary success denominator.

Report actual pass@1, oracle pass@k separately from any implemented selection, per-skill acquisition, source-correct lost rows/denominators, acquired-A retention before/after B, UNKNOWN recall, false abstention and parent-clustered uncertainty. Net gains cannot cancel loss counts. No nonsignificance-to-equivalence conversion. All included evaluations are exposed, not sealed. Final margins, power, source-correct membership and native token budgets must be prospectively bound; no inherited numerical gate or historical result is changed.
