## Prospective semantic clarification

The original proposal said three necessary facts per world. This amendment makes
that **three necessary evidence record blocks**, with multiple scalar entries in
two blocks. This change is made before production/outcomes to avoid pretending
that lookup alone tests numerical/latest selection.

The three_fact_keyed_join identifier now denotes a numeric range join: a consignment
mass, three nonoverlapping mass intervals mapped to depots, and depot-to-seal values.
A mass moved across an interval boundary must change the answer. The second family
uses an authorization block, a four-entry revision/time/writer catalog (two entries
per writer), and a revision-to-value mapping. Authorization varies independently
of timestamp ordering, so neither writer frequency nor the globally newest writer
reveals the authorization value. Swapping the
authorized timestamps must change the winner; a newer unauthorized entry must not.
Deleting any one whole required block must yield UNKNOWN under an independent
visible-text solver. No claim is made that every scalar inside a block is necessary.

Aliases and display order must not encode a fixed winner. Vary authority/revision
aliases, winner rank, interval selection, and the independently shuffled catalog/
value-table order. Normalize alias-only changes in semantic identity so a renamed
world cannot move role. Preserve substantive numeric relationships in the identity.
These are distinct sampled numeric worlds within only two structural mechanisms;
32 worlds do not prove 32 independent reasoning mechanisms.

The missing-evidence twin removes exactly one block, chosen prospectively and
counterbalanced, and substitutes an irrelevant NOTE in the same fixed-width slot.
Other blocks/query/token offsets remain unchanged at each length. Multiple candidate
symbols may remain in the value table when another required block is absent; the
visible problem must still be underdetermined. Query, instructions, filler and
decoys must not identify the hidden winner or restore the missing dependency.

Each adversarial rendering has three compact decoy records: one for a different
key, one same-key ARCHIVE record explicitly labeled obsolete, and one same-key
UNSIGNED record explicitly labeled unauthorized. Thus all three modes occur once
per adversarial world, avoiding an uneven division of 32 parents into three modes.
All shadow the fixed missing-dependency index with wrong content; the answerable
and unanswerable renderings use identical decoys. Their syntax is validated, and
the declared evidence rules make ARCHIVE/UNSIGNED assertions nonbinding. Neutral
renderings replace them with three irrelevant NOTE lines at the same token width.
This does not claim resistance to arbitrary prompt injection or unmarked deception.
Shadow keys and payloads must be independent of the hidden winning revision/depot;
changing the winner while holding aliases fixed must not change a decoy to reveal
which value-table entry to choose. The original three-entry catalog and any
winner-dependent shadow construction are superseded before production.

## Exact tokenizer fit

Use the pinned local Qwen tokenizer, non-thinking chat template, no model/Torch
backend, no downloads. The complete occupied prompt lengths are exactly2024/4072,
not word-count estimates. All required block span endpoints lie within body-relative
token bands early[.10,.20], middle[.45,.55], late[.80,.90]; distributed has one block
per band. Record native token offsets after the final full-template rendering.

Fit only complete, predeclared solver-irrelevant NOTE prose, with no PAD/EOS filler
or truncation. The bounded additive-note dynamic program has at most4072 budget
states,128 common-slot-width candidates and32 placement-offset candidates. Validate
actual token concatenation and offsets, never assume additivity. A construction
failure fails the whole bank and preserves a failure receipt; no dropped parent,
changed quota, relaxed band or automatic retry. Wall ceiling1800s.

Every DEV row must pass independent visible-text solving, strict target parsing,
all-block ablation/decoy controls and paired-span checks. Targets are short symbols
or UNKNOWN, at most16 native tokens. Freeze script/registration/tokenizer/prompt/
bank hashes before any future model scoring. CHECK receives identifiers only.
