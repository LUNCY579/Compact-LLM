`cases.audit_prepared_inputs` reads only the sixteen pinned training artifacts
and prospective DEV membership. It records family/style/sign/branch/scenario

It never opens the final archive, old banks or checkpoint weights.

Static source inspection identified these patterns, pending the row-level audit:

- Hard diverse ledger examples associate canonical/native_b with positive
  operands and native_a/natural with negative operands. No-replay fresh training
  has 125 examples per style; replay fresh training has 100 per style.
- Diverse conditional-register examples associate canonical/native_b with the
  true branch and native_a/natural with the false branch. Hard examples also
  associate conditional operand sign with style. Fresh conditional totals are
  248 without replay and 200 with replay.
- Regular answerability construction has positive supported numeric golds only.
  Hard construction adds negative supported golds, while its styles receive
  different scenario/sign combinations. Difficulty therefore changes more than
  pairing or an abstract hardness level.
- Fresh conditional margins are constructed as zero or one. Both branches are
  present, but wider comparisons are untested by this construction.

These are deterministic input properties, not observed model effects. Missing
gold signs, narrow margins and different difficulty populations need explicit
prospective data decisions. The optional style-assignment map is **UNADOPTED**:
it balances observed semantic cells while preserving exact family/style totals,
but cannot manufacture absent cases. It is never substituted into training;
applying a revision would require new format rendering, leakage/token audits,
source/data identities and review before native outcomes.

style's result versus its own canonical parents. Attached rows add no independent
worlds. Empty inputs produce **UNMEASURED**. Caller summaries are untrusted; this
pure report authenticates no native result and changes no selection/final gate.
