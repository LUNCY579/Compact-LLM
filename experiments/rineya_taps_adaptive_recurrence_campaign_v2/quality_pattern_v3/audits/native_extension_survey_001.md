## Concrete extension points

The frozen operator has a useful decision boundary. In `experiments/rineya_taps_adaptive_recurrence_v1/integration.py`, `BlockRecurrence._forward` retains the input to L12 as `old`, completes ordinary L13 as `normal`, and observes `d0 = normal - old` before entering the extra-pass loop. It then calls the saved L12 and L13 forwards on `normal` to obtain `proposal`, observes `d1 = proposal - normal`, and applies the scaled extra update. L0–L2 and the full L14–27 suffix/custom head remain one-shot per full-model call. A successor can add a decision at this boundary without replacing weights, the readout, or either saved block callable.

| Feature / decision | Earliest availability | Compute implications |
| --- | --- | --- |
| Last-token ordinary residual norm, residual/state RMS ratio, cosine of block-entry and ordinary block-output state | After ordinary L13, before the extra pair | Can support a genuine K0/1 decision that skips the extra L12–13 pair when K0 is selected. No additional full-model call is intrinsically required. |
| Last-token `cos(d0, d1)`, update norm ratio, or ordinary/proposal state cosine | After the extra pair, before scaled update | Can support attenuation of that already-computed proposal. It cannot support a claim that K0 saved the extra pair: K1 compute has already occurred. |
| Current full-prefix two-observation balance B | After the extra pair | Same limitation. The first, single-observation balance has zero fluctuation and is effectively a unit positive warmup statistic, not an opposite-direction predictor. |
| Intact full-head UNKNOWN versus nonUNKNOWN margin | After the intact L14–27 suffix and custom head | Requires an intact full-prefix pilot before a head-margin-based decision. A K0 result can reuse the pilot logits; K1 requires another full-prefix call. The wrapper cannot read this margin at ordinary L13 without executing the suffix. |

`control.py` inherits the frozen operator and resets moments at each complete prefix forward. Its A5 RNG stream persists only within a case/arm/seed context. A new decision must preserve that separation, wrapper ownership, restoration, cache rejection, masks, positions, and timing hooks. It must not modify the frozen classes in place.

The supported scale operation is `scheduler.apply_update(normal, proposal, alpha)`. At alpha exactly 1 it returns `proposal` directly, avoiding subtraction/addition cancellation. A successor must preserve this branch, including effective FP32 unit values. Existing bounds are 0.8–1.2; attenuation 0.8 or 0.9 already has fixed-control qualification evidence, but a new feature-selected rule still needs its own qualification. Alpha zero is neither within those bounds nor a compute-saving K0 mechanism. A genuine K0 branch returns the ordinary state before computing the proposal.

## Readout measurements and their limits

`gpu_native.forward_logits` returns the final FP32 last-position logits after the actual suffix/custom head. `evaluate_case` obtains the first-prompt vector before greedy token selection and returns it to the caller. `bulk_restart_native.py` retains these vectors temporarily for paired readout statistics, then writes only scalar diagnostics. Neither its readout journal nor `armr.metrics.logit_metrics` stores the UNKNOWN margin. Existing `margin_change` means the change in top1-minus-top2 margin; it is not UNKNOWN-versus-answer margin. Historical UNKNOWN margins cannot be reconstructed from those scalar journals.

A prospective measurement can record `z[51378] - max(z[j], j != 51378)` and the corresponding rival ID from an intact A0 pilot. Define the rival set explicitly: unfiltered nonUNKNOWN vocabulary includes EOS and other special tokens, so the scalar is not automatically an answerability score. Record the raw UNKNOWN/rival logits, IDs, and shift-invariant margin; do not alter logits, head bias, decoding, or use the canonical answer to choose the rival. The model has 151,936 embedding/head rows, while the tokenizer has 151,669 entries; indexing and decoding coverage are separate checks.

A prompt-level margin gate pays at most one additional full-prefix pilot per case when K1 is chosen. A per-generated-prefix margin gate can approach twice the full-model calls of the chosen K1 rollout and requires precise pilot reuse and attempt accounting. Generated-prefix features are causal but are not original-input-only features. For the requested original-input predictor, freeze the first-prompt feature object and decision before generation; do not update it from teacher prefixes, losses, outcomes, or future tokens.

## Recommended minimal qualified measurement

First build a passive feature apparatus, with no candidate routing or learned parameters: run all 192 source-bound DEVELOPMENT original prompts under A0 and unit K1, one first-prompt full forward each. This is 384 task forwards, zero adjoints, no generation, and no teacher prefix. Capture ordinary last-token features in both paths and `d1` last-token features only in K1, plus each final readout margin. Store each feature's stage and availability, prefix hash, scalar operands, denominator/zero handling, finite flag, and frozen object hash. Features that need `d1` must remain labeled proposal-dependent; they cannot be passed off as pre-extra budget features.

This packet can test whether distinct input-only measurements separate opposite observed directions where unsigned B did not. Pair it offline with the already-complete per-case K0/unit/fixed-attenuation outcomes and the existing canonical-prefix derivative diagnostics, keeping those two labels separate. A first-prompt readout or derivative association is not a full-response quality gain. Cases with ties/no scale sensitivity must remain in the descriptive tables. Parent/variant and answerable/unanswerable breakdowns are needed because false-UNKNOWN repair can accompany unsupported-answer harm. Current labels and all validation inputs are already exposed: this is exploratory evidence, not fresh confirmation.

If the measured features justify a rule, the next prospective candidate should be the smallest frozen input-only rule: either a first-prompt pre-extra K0/1 gate, or a bounded attenuation rule after a proposal. Select between them according to feature availability and the observed distinction; do not combine mechanisms merely to add flexibility. Freeze the rule and thresholds using explicitly registered DEVELOPMENT calibration, with parent-disjoint internal assessment if fitting is proposed. No canonical targets or offline favorable-arm labels may enter the online feature object. Full greedy generation with all required fixed/unit/intact and matched-control comparisons is then necessary to establish quality and preservation. The passive packet alone cannot satisfy the new quality-gain goal, and it does not replace or narrow the completed full-matrix evidence.

For a head-margin gate, first decide whether the initial-prompt pilot cost is acceptable. It is an alternate apparatus, not a free feature added to the pre-extra gate. The conservative option is to keep the first measurement passive and avoid pilot reuse/controller branching until independently tested.
