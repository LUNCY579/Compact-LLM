# Research policy 10: source and bound numerical consistency checks

PROPOSED; independent acceptance required. This policy grants no native attempt,
controller fitting, training, protected data, resource or production authority.

Observed failure: the complete native003 matrix passed its registered source,
finite-difference, preservation and resource gates, but analyzerbfe6 rejected one
EOS target at three scales because a cross-implementation ordering inequality
used an unsupported fixed1e-5 tolerance. Actual logits/LSE operands were not
saved. A no-model, representable-logit shift counterexample proves the threshold
can reject valid FP32 computation; it does not prove the actual case's cause.
The frozen failed report and original analyzer/raw run are preserved.

Procedure change: before a numerical relation becomes a must-pass proof gate,
state the actual operations/dtype, retain the operands needed to bound error,
and justify its finite-precision envelope. Exercise an operation-specific
invariance/counterexample fixture where appropriate. If no valid bound exists,
mark that relation UNVERIFIED and expose all raw discrepancies; never choose a
larger tolerance from observed errors, clip values, drop cases or switch endpoints.
Registered native/FD, finite, source, EOS-ID, chronology and count gates stay fixed.
Any proposed change to those registered gates needs its own prospective review.

Use a separate postrun analyzer successor, immutable raw evidence and exclusive
new output when correcting an analyzer assumption. Its source/test/protocol
lineage and changed functions must be independently reviewed before interpretation.
Future EOS instruments should prospectively log LSE operands/max-logit magnitudes
when an absolute ordering-accuracy claim is intended, without borrowing this
old run's qualification or authorizing a new model call.

Acceptance for this scoped correction: oldbfe6/tests/plan and native97 closure
still match; new5a624 source changes only triplet precision metadata, aggregate
metadata/status and output text; all required count/prefix/feature/state/vector/FD
and statistical helper functions remain unchanged. All192 EOS rows and raw
values/gaps remain; original1e-5 exceedances stay descriptive, all ordering remains
UNVERIFIED. Independent changed-fixture tests must reject bad FD/EOS IDs,
nonfinite/missing EOT and incomplete source/count proofs and reproduce unchanged
primary/EOS endpoints when the old extra checker permits them. Raw recomputation
must match the exclusive corrected report with no survivor selection.

This remedies a specific analyzer-assumption failure. It does not establish
research-allocation efficiency, exact EOS probability accuracy, long-run GPU
stability, task correctness, adaptive controller efficacy or model/agent self-
improvement. Native actual cost remains charged; no retry followed this defect.
