## Verifier, score and discrimination

Construction computes gold from generated world state/formula. A separate raw
prompt parser reconstructs ledgers, rules, current program registers, chronological
dialogue state and source authority. It takes only the prompt string; no case
metadata/gold is available. Gold/status checks occur afterward. Public tests also
verify hand-specified branch, quotation, withdrawal, latest-date and conflict cases.
Human review remains NOT_REVIEWED; independent agent code/data review is required.

Strict scoring imports the frozen OPEN gold-independent normalizer without
modifying open_bank.py. Full canonical integers and exact YES/NO/UNKNOWN after
outer whitespace/case normalization are admitted by each prompt's answer kind.
No last-number/choice, negated keyword, prose repair, JSON coercion or punctuation
forgiveness. Literal UNKNOWN, canonical abstention, false UNKNOWN and unsupported
canonical answers are distinct. Natural-language abstention is NOT_ASSESSED,
not silently counted as an unsupported answer or solver-certified semantics.

Tested prompt-only floors include constants, full-copy, first/last numbers,
last entity, query-blind first/last-entity solvers, last printed queried number,
rule-RHS-presence skeleton, and any-clear/max-value dialogue heuristics.
Code magnitudes are randomized independently of event age; known histories
include CLEAR followed by redeclaration, while hard missing histories include
redeclaration followed by withdrawal. Quotations occur in both outcomes.
Tables report whole bank,split,category,
generator/variant,difficulty,matched variant and category×split×difficulty.
Chance50% binary/UNKNOWN endpoints remain explicit. Gross prospective gates:
no single tested attacker above144/288 globally and none perfect over a whole
category. These gates do not certify all shortcuts; family/stratum rates and
small denominators must accompany model results.

Exactly one recorded nonce and seed17 produce the exported packet. No nonce
search, seed search, outcome-based selection, survivor deletion or hidden
validation data. Every case is written before auditing, with failures retained.
Failed data admission requires a concrete prospective correction, not regeneration
under a more flattering nonce. Tests use separately labeled CPU fixtures.
