## Verified presentation pattern

If the public request unambiguously declares one string-valued JSON field and the
generation is complete, preserve all existing objects and wrap an eligible complete
scalar under that field. Preserve the chosen string or scalar spelling; never infer
the answer, field, latest record, uncertainty or null from gold. Null is allowed only
by the public request. Arrays, ambiguous/multiple-field requests and unsupported
responses remain unchanged. The optional bare-token mode was disabled in the replay.

`public_schema_repair.py` implements that rule and the narrow public-request grammar.
For these object-valued targets, every previously strict/typed-correct object stays
byte-identical; repair is idempotent. This conditional property is deterministic.
It is not a guarantee of better reasoning or correct new answers.

## Why this is not a safe quality recipe

The old contract metric derives primitive types from the target. In a publicly
nullable string request, a returned string can satisfy the public schema while
being wrong because the correct answer is null. Keep that original endpoint intact
and report actual public-schema compliance separately.

On the640 supported single-field requests, public-schema compliance changes
76→598, but schema-valid target-value mismatches change45→284: **239 additional
wrong answers become structurally acceptable**. Under the original target-conditioned
contract metric, the corresponding mismatch count is53→260 (+207). These different
denominators and definitions must not be pooled or called broad semantic accuracy.

All32 absent-evidence cases still fail the registered correct-null endpoint. All32
now satisfy the public nullable-string schema while selecting a non-null wrong value.
JSON validity, schema validity, exact value correctness, abstention and independently
qualified semantic correctness are separate properties. Do not deploy the wrapper
or use schema compliance as semantic verification from this exposed replay.

## Verified data shortcut

The existing missing-evidence generator also admits a query-blind absence classifier.
Counting unique entity IDs in record lines alone gives two entities for every present
case and three for every absent case. The probe predicts32present+32absent correctly
on all64 existing DEV rows, without seeing the query or target during prediction.
It is a deterministic corpus shortcut, not a Rineya capability result or general solver.

Future absence studies should balance record/entity/field counts and layouts across
labels and vary queries over unchanged factual contexts. Otherwise a null-supervision
gain could reflect nuisance counting rather than entity-field binding. Do not repair
the current frozen corpus retrospectively or relabel its exposed data as confirmation.

## Learned-pattern leads and counterexamples

Historical matched MQ pairs favor response+EOS supervision in each of three orderings:
13/51 versus7,7,8/51 on whole-prompt training. They reused one238-row training draw
and the same DEV cases; the source-correct support is only3. Different supervised
denominators (1,944 versus24,672) alter response weighting, so mask correctness and
optimal loss weighting must be distinguished. Missing checkpoints and incomplete
historical supervisor coverage also prevent GD trajectory admission.

The result is a candidate mechanism, not a universal response-only law. Other
regimes benefit from moderate prompt weighting in [WIT](https://arxiv.org/abs/2507.07817).
A future qualified objective ablation needs independent draws/fresh families and
controls for effective gradient scaling, while measuring value selection and
source-correct preservation separately from formatting.

Missing-condition supervision and teacher fidelity are likewise insufficient
preservation surrogates: BINDING condition repairs coexist with false UNKNOWN and
fixed-source retention failures; derived-student teacher-KL gains do not certify
abstention. Existing DSD/RDD/RSD readiness is not native efficacy evidence.
