# GD-001 — Rineya checkpoint generalization dynamics

**Status: implemented, mechanically tested; native Rineya compatibility and efficacy remain unqualified.**

A dedicated, read-only experiment for the exact **0.6B-class Rineya** campaign:

> Along one fixed post-training trajectory, can development-only checkpoint selection
> improve resistance to misleading cues and fresh R+S composition, relative to the
> final checkpoint, while preserving clean competence and a fresh retention probe?

Inspired by Wen et al., **Generalization Dynamics of LM Pre-training**, arXiv:2609.33150v1,
27 September 2026: https://arxiv.org/abs/2609.33150v1 . This is an original small-model
adaptation, not a reproduction of GDsuite, the authors' pre-training campaign, or their
reported results. No third-party implementation or evaluation data are copied.

This experiment complements post-training, cumulative-skill, and recurrence research.
It does not supersede their gates or imply a new architecture is necessary.

## Delivered pipeline

| Module | Responsibility |
|---|---|
| `diagnostics.py` | Deterministic clean/misleading pairs; separate DEV/confirmation templates; linked R, S and R+S cases |
| `registry.py` | Exact local HF/LoRA snapshot and tokenizer hashes; step ordering; same-config checks; training-overlap audit |
| `integration.py` | Post-save receipt hook for existing trainers; no optimizer changes |
| `native.py` | Explicit, offline, sequential HF/LoRA inference; strict loads; greedy generation and full answer-token scoring |
| `metrics.py` | Generated correctness, shortcut rate, competence-conditioned robustness, reference-fixed retention, linked composition, paired changes and cluster uncertainty |
| `pipeline.py` | Frozen registration -> development sweep -> immutable selection -> single-use confirmation -> report |
| `cli.py` | Runnable entry points, synthetic demo, and fail-closed preflight |
| `tests/` | CPU mechanical, state-machine, adversarial, and optional real-PyTorch tensor-contract tests |

The default suite has **144 logical pairs / 288 prompts per checkpoint**: 24 pairs each
for successive-answer arithmetic, repetitive-answer arithmetic, retrieval R,
transformation S, R+S composition, and a fresh short retention control. Linked R/S/RS
cases share underlying quantities. The bootstrap keeps those related cases together.

Confirmation is **not generated by initialization or the development sweep**. It is
created only after checkpoint selection is locked and confirmation access is explicitly
requested. An interrupted confirmation attempt remains spent.

## Try the complete mechanical pipeline

From the repository root, with a new output directory:

```bash
python -m unittest discover -s experiments/rineya_generalization_dynamics_v1/tests -v
python -m experiments.rineya_generalization_dynamics_v1 demo --run /tmp/gd001-demo
python -m experiments.rineya_generalization_dynamics_v1 report --run /tmp/gd001-demo
```

The demo intentionally uses gold-aware fixture predictions. Every receipt is labelled
`mechanical_fixture`; **its scores are not Rineya results**. It does not load or train a
model, download anything, or read any existing repository evaluation bank. Without
PyTorch, the eight tensor-contract tests explicitly skip; the other 57 tests need only
the standard library. The delivery environment ran all 65 without skips.

## Native boundary

Native inference is implemented for standard, local Hugging Face causal-LM safetensors
exports and matching standard LoRA adapters. The exact base parameter count must be
registered and match the loaded model; the admitted range is 500M-700M, not 344M.
There is no stock-Qwen, random-model, remote-code, quantized, custom-readout or
missing-weight fallback. Unsupported Rineya formats must be exported and independently
qualified using their existing native infrastructure; this experiment does not perform
an unverified conversion.

**No native checkpoint was loaded in this delivery.** The complete HF/PEFT loader and
resource guards still require qualification on the actual host. Real PyTorch tests here
exercise tensor arithmetic with a tiny deterministic stub, not a Rineya model.
