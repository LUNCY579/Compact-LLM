agreement alone does not identify an internal model circuit.

On the fresh saved anchor outputs, all 32 missing-evidence cases failed correct

the largest payload and 66 matched the latest payload. These exposed diagnostics
motivate separating three operations: bind entity and field, compare the named
key, and return its separate payload. They do not prove that explicit supervision
of those operations will help Rineya.

## Exhaustive finite witness

The new `query_dependence_witness.py` constructs an excluded mechanical fixture.
Its exhaustive version contains all 90 binary 4×4 relations with row and column
degree two. Every context has 12 records, six entities, fixed entity/field
frequencies, the same value multiset and four fixed nuisance records. All 16
entity–field queries see exactly the same factual bytes within each context.
Each context has eight present and eight absent queries; every fixed query is
present in 45 contexts and absent in 45. IDs and oracle metadata are outside the
public input.

Independent recomputation checked all 1,440 typed targets and the conditional
bounds. A rule using context alone, entity plus context, field plus context, or
query without context can achieve at most **50%** exact typed correctness on this
complete finite population. Null occurs in half of each relevant group, so the
context-only bound is 8/16, not 1/16. The fixed entity-count heuristic likewise
cannot exceed 50% here. These are mathematical bounds on specified information
sets, not native scores or proof that a model reads its query.

The reviewer also independently checked 2,880 record-permutation, 1,440
nuisance-value and 5,760 selected-value oracle properties. A separate relation
switch changes answers while preserving marginal counts. These checks establish
lookup semantics only. They do not measure model invariance, revision comparison,
learning, retention or quality. Equal character width does not establish equal
token length; query ordering and cross-example carry-over remain potential leaks.
