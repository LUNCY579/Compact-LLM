# GD-001 continuation rules

Keep this experiment isolated. Read README.md, PROTOCOL.md and RUNBOOK.md first.

- Do not modify main, the integration branch, other experiments, production code,
  historical evidence, existing gates, or model weights as part of this experiment.
- No old sealed, SPENT, barred, confirmation, or ANY_READ bank is authorized by this
  package. Only its fresh DEV diagnostics are available before the selection lock.
- Never turn the gold-aware mechanical fixture into native evidence. Tests and tensor
  stubs do not establish a native model-quality result or HF/PEFT compatibility.
- Never weaken host/GPU/disk guards, silently truncate prompts, fallback to a different
  checkpoint, enable remote code, or kill an unrelated process.
- Do not change thresholds, code, data or runtime inside a registered run. Preserve all
  receipts, blocked outcomes and consumed confirmation markers. Do not rerun a spent
  confirmation bank under a new filename or seed to obtain a favorable result.
- The post-save hook does not authorize training; use existing independently approved
  trainers and local qualified exports. This project remains 0.6B-first, not 344M.
- Retain this experiment as complementary evidence. A null result is informative;
  neither null nor positive synthetic diagnostics supersede broad retention gates.

Before pushing, run the scoped unittest suite, compile the package, and check whitespace.
Record native qualifications and limitations separately from mechanical test results.
