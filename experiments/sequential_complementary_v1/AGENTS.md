# SCP-001 implementation and continuation rules

Preserve both parent research branches and their historical registrations. This
package is additive. New work must follow the user's isolated-branch rule. Do not
change catalogs, original model bytes, old permits, or frozen evidence.

Read README.md, protocol.json, SOURCE_PINS.json and the parent RRP AGENTS.md. The
headline correction is binding: k=.25 is per-tensor magnitude masking, not scalar
scaling. Titan-Sparse requires FP32. Teacher availability is not established by a
local headline; do not invent its checkpoint or classify 596M draws as 4B replication.

Run scoped CPU tests and independently inspect failures. A fixture PASS is not a
native PASS. Dataset mechanics alone are not data acceptance; preparation alone is
not training; algebraic factors are not a qualified serving model. The native launch
refusal is intentional until a real exact-subject supervisor integration is added
and tested. Do not remove it merely to make a status table green.

All read permissions, model identities, masks, data/prompt policies, numeric
budgets, failure costs and storage requirements must be explicit before native
execution. Reuse the inherited supervisor and trainer without relaxing their
checks. No paid resource, background task, protected-bank read, release or production
promotion is authorized by this package. Keep raw outputs and failed attempts.

Use external evidence directories and create-only files. Keep TRAIN/CAL/CHECK
structurally disjoint. Missing authorized fingerprint coverage blocks acceptance.
No teacher-success filtering or post-outcome prompt changes. Freeze old/new
inference policies before training. Report repairs and damage, actual tokens and
wall time, and estimator limitations rather than only aggregate accuracy.

After every commit, verify its remote branch head AND changed-file Git blob hashes.
Never claim a push succeeded from a local commit or unreferenced Git tree alone.
