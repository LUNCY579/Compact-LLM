# CPU preparation for complete raw-response provenance

`score_import.py` imports independently audited M0 responses into a complete,
unscored compact002 packet. It binds all 384 rows and 96 joined components,
ordered prompts/tokens, family/condition/rendering routing, frozen scorer and
statistics sources, raw responses, generation metadata and audit provenance.
RS remains held out from adaptation. Partial populations cannot be scored.

Audit/config file hashes must be selected through a trusted external reviewer
or supervisor. Matching caller-supplied hashes authenticates the selected bytes;
it does not establish auditor identity or certify arbitrary self-signed files.
Private native loader records are reread before admission. The adapter verifies
preserved config, source, worker, final-row and ordered input joins. Model,
runtime, resources and generation traces remain authority from the independent
native audit; this adapter does not load weights or qualify a launch.

Actual M0 batches 01–03 contain only 192 of the required 384 rows. Failed batch
04 and partial native imports are rejected before any grader callback. Native
M1/M2 collection schemas are absent and explicitly rejected. No actual grading
API or authorization is added. A private synthetic factory permits CPU fixture
callbacks only; resealing the real evaluation registration as a fixture cannot
reach a callback.

The [reviewed staging history](evidence/score_import_reviewed_cpu_20261005)
preserves the rejected 28-control predecessor and corrected 32-control version.
All [32 root controls](evidence/score_import_root_cpu_validation_20261005.json)
pass, including native identity rebranding, partial and failed batch rejection,
forged native descriptors, population/order drift and stage/root portability.
No captured response was graded, and no framework, model, GPU or solver ran.

Before actual scoring, freeze a source- and receipt-bound policy specifying
how valid whole-response JSON ending at the 32-token generation cap is treated.
Bind the whole-response parser, generated-only decoding/audit evidence,
complete population/order and all three arm/checkpoint identities. Both EOS
and cap outputs currently remain unscored. Existing strict JSON verification
does not by itself supply this finish policy.

Candidate imports must later require actual qualified final-27/540 study
checkpoints, three complete chunks and their publication/cost lineage.
Qualification checkpoints cannot substitute. Native sustained/resume fit,
M0 retention enrollment, qualified language authority, long-context execution,
all retention domains and the registered paired analysis remain separate gates.
