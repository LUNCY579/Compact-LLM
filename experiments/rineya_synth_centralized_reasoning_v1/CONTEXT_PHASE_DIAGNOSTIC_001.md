# No-model context-phase diagnostic

The integrated contract, worker and supervisor define a separate diagnostic
purpose. The manifest rejects model directories/weights, rows, checkpoints,
model construction, forward/backward, training and grading fields. The worker
imports framework/class symbols lazily after owned admission, but has no model
loader, tensor workload, cache reclamation, device reset or external process
control path. Framework/driver imports may allocate internally; observing those
allocations is not model execution or model qualification.

The exact executed source roster,65-entry runtime (original64 plusAST), offline
environment, seven original helpers and profile must be pinned. Resigned source
omissions fail. Every import/version/growth-reserve/context/memory/config/seed/
process-peak-statistics boundary has durable started/returned/failed records,
monotonic/UTC timestamps and counts. A nonrecursive read proxy meters the original
guard's CUDA queries exactly once, preserving result objects and exceptions.
False initialization skips the memory query as before. This includes the guard
after `cuda_context_init` returns, which precedes the explicit preload query and
was unlogged in the failed collector. Publication errors retain original guard
errors and partial costs; a started marker is not an exact program-counter trace.

Existing ownership/containment/lease/sampler cleanup and all resource limits stay:
100ms CPU cadence,200ms freshness,4GiB GPU admission/preload,0.5GiB during work,
3.3125GiB preworker available RAM,1.25GiB reserve,2GiB owned RSS,4GiB disk and600s.
Pinned NVML remains resource authority. Optional Windows process counters record
unsupported/unavailable status explicitly and cannot replace NVML or establish
past allocation attribution. Resetting process peak counters follows the original
phase; it does not reset a device or reclaim another application's memory.

The [reviewed history](evidence/context_phase_diagnostic_reviewed_cpu_20261005)
preserves the12-control candidate and package-portability fix. Independent staged
and fresh-root12 controls pass. All
[12 root controls](evidence/context_phase_diagnostic_root_cpu_validation_20261005.json)
pass, with seven original helper hashes unchanged and isolated CLI startup.
The initial validation-harness helper lookup failure and correction are retained;
production bytes were unchanged. No framework/GPU, model, NVML/Win32 or capability
measurement ran in these CPU controls.

A real diagnostic still requires a reviewed write-once manifest, committed exact
source/runtime maps and fresh owned admission. Its output could narrow the failed
resource phase; it cannot itself prove the historical cause, collector fit,
learning, transfer, retention or permission for a study run. No actual diagnostic
manifest or native result was created by integration.
