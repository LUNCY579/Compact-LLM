# Shared-entry CPU terminal consumer

The staged auditor now replays the six startup phases in the same `replay` and
`_core` functions used by the existing terminal consumer. Its private
`_CPU_shared_entry_bytes` seam uses the original bounded `Reader`, compares
original and preserved bytes and complete raw rosters, and rechecks read sets.
It supplies no supervisor, Job, resource, death or library qualification.

Seven authored controls pass on the frozen placement/category003 producer.
They execute the original durable writer and injected core with private inert
entry actions, then read and replay the copied bytes. Controls cover complete
CPU evidence, mixed source/cache read and descriptor-hash costs, resealed cost
and order forgery, source-pin override, pre-core failure without worker_result,
cleanup failure and failed final publication. Framework and native imports are
trapped. Fixture-layout copies retain producer bytes; their location supports
the producer's original package-path selection and is not a native witness.

Startup/core success requires exact single operation counts and original guard
order/query ceilings, with at most 128 markers. Boundary categories are bound
to finite source wrapper names. Source/cache returned calls and observed byte
totals derive reads/bytes; source/cache/IO attempted calls derive IO_calls;
API attempted calls derive API_calls. IO_calls counts selected boundaries,
not every internal operating-system call. A boundary wrapper contributes no
duplicate bytes. Selected compiled-source pins and the three writer-bootstrap
pins must match an externally selected map and current source bytes.

The original b06fa082 auditor is preserved in `pre_entry_auditor001`.
Intermediate variants and receipts remain in `pre_entry_auditor002` and
`pre_entry_auditor003`. The first control receipt contains five fixture-layout
errors; controls005 contains a deliberately tightened accounting diagnostic
that found stale producer accounting on failed publication. Those are retained
as failures, not added to the passing test count. The corrected producer
refreshes failure accounting; missing final publication is still explicitly a
failed partial record, never a completed run.

The native shared-entry `_core` path is explicitly closed. Existing native
scope, exact core predicates, resource checks, byte preservation, leases and
all-birth death checks remain in place. This is a CPU consumer milestone;
it does not make the tensor run packet runnable or confer native permission.

The next finite native composition must:

- Join `entry_bootstrap_sources` and `selected_boundary_source_pins` against
  the registered manifest before invoking the same categorized-cost replay.
- Publish a source-defined early-failure report using the actual durable writer
  in cleanup phase 6 when that writer is available. Membership/runtime execution
  fields must remain unavailable if their operations never ran. Writer failure
  may leave only truthful SUP partial-output evidence.
- Branch the existing `_native_preserved_body` RAW_CORE/OWNED_WORKER_RETURN
  requirements for that early-failure shape, while retaining original
  supervisor/admission/resource/lease/death checks. Successful native evidence
  retains exact membership and runtime-source joins.
- Review that composition before lifting the explicit shared-native refusal.

No native worker, observer API, DLL, CUDA, Torch, tensor or model ran in these
controls. Native event proof and whole terminal consumer qualification remain
unestablished.
