# Next owned startup and observer measurement

This prospective proposal removes a code-created cycle. The previous observer-only contract requires a qualified fresh bootstrap and an exact loaded-module baseline before the worker can measure either. Those requirements are not host observations. The prior source packet and every prior failure remain preserved.

The next native scope should use a finite passive byte inventory as its input, then produce actual startup/module observations. It must not accept a fabricated baseline or a positive qualification boolean as a substitute for the run. The scope remains separate from all model, CUDA, tensor, decoder, training and scoring work.

1. Verify the committed source, interpreter, selected runtime files, fixed offline environment and explicit owner permission. Refresh owned resource admission under the unchanged original limits.
2. Start exactly one fresh isolated interpreter under the existing suspended process, owned Job and watchdog lifecycle. Record interpreter identity, owned process birth, environment, Python module origins and the permitted ctypes bootstrap imports as observations. Do not claim arbitrary live namespace or cached-code execution provenance from file hashes.
3. Enumerate its current Windows module population twice with bounded reads. Preserve original paths/handles, including any unresolved or unselected module. If any selected byte or baseline check fails, preserve the failure and stop before loading the fixture. The first startup baseline is an output, not a predeclared exact population.
4. If every observed module is selected and byte checked, bind the compiled observer and record its actual ABI/handle. Register notifications, load and unload the inert fixture once, capture bounded module snapshots, unregister and drain. Preserve source/runtime rechecks, original exceptions and every owned terminal state.
5. Run the independent terminal auditor on original bytes. Qualify only the observed process/window/ABI and fixture load-unload behavior if all required measurements pass. Any later tensor launch needs its own approved registration and fresh admission. No study score or transfer claim follows from this probe.

Keep the current 600-second whole-scope limit, 4 GiB GPU admission floor, 0.5 GiB during-work floor, 2 GiB owned RSS ceiling, CPU/GPU freshness bounds and all remaining resource checks unchanged. This probe allocates no model tensors and creates no CUDA context. It grants no authority to stop unrelated GPU processes.

This is a reviewable sequence proposal, not an executable launch manifest. The exact revised committed dispatch sources, measured passive byte receipt and owner approval must be recorded before any run. Package AGENTS.md requires separate manifests and explicit permission for new native scope; the owner's request to continue CPU work authorizes the present preparation only.
