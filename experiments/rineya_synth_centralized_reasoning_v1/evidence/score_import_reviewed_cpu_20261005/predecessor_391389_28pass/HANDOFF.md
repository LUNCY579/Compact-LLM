# Staged pre-score raw import

This CPU preparation preserves the study: unchanged M0 versus M1 verified
surface variation versus M2 condition diversity, all 384 frozen DEV rows and
96 joined components, RS held out, plus all required retention domains. It is
not integrated source, scoring authority, a native launch, or a study result.

`score_import.py` binds compact002 panel/public prompts/public tokens and the
eight preserved panel/scorer source files. It derives family/component routing
from the frozen parent roster without reading the oracle sidecar or solving a
prompt. `panel_metadata_sha256` uses the existing statistics metadata convention;
the original collection order is separately retained and enforced.

`load_m0_batch` requires independently selected audit and config **file** hashes.
It verifies successful audit status, canonical bodies, stable audit hash closure,
preservation/config/source joins, preserved worker/final-row bytes and the
audited ordered row manifest. Its private loaded records are required for native
imports and reread before admission. Native registrations are rebound to the
actual pinned compact002 files and source closure, so recomputing a caller-made
checksum cannot admit an altered roster or a fabricated audit-pass flag.
Model/runtime/resource closure remains evidence from the prior independent
audit; this adapter does not reread model bytes or requalify a launch.

`prepare_import` requires six ordered audited batches, exact prompts/tokens,
unchanged model references and the complete384 denominator. Each joined record
retains family, condition/rendering/component, arm and complete raw response,
IDs, trace/logprobs, costs, EOS/cap/truncation metadata; batch references retain
audit/config/preservation/raw/source/model hashes and source commit. It produces
an unscored packet. Actual batches01–03 supply only192 rows; batch04 failed.
Their negative controls reject without a grader callback. Native M1/M2 receipt
schemas are absent and are explicitly rejected rather than invented.

`score_cpu_fixture` is an injected callback control for clearly synthetic rows
only. It validates the full population first, passes the entire decoded response
and finish metadata, and rejects native scope before the callback. It creates no
qualification or quality authority. Existing `evaluation_panel.verify_response`
already independently parses visible prompts and strict whole-response JSON;
there is no new solver or last-JSON extraction here.

Before any actual grading, register a source/receipt-bound scoring policy that
explicitly specifies correctness treatment for valid whole-response JSON whose
finish is `generation_cap` at32 tokens, including its interaction with the
existing strict answer parser. Bind that policy to the exact scorer source
closure, generated-only decoding/audit evidence, frozen population/order and
all three arm/checkpoint identities; provide independent qualification evidence
and explicit scoring authorization. This preparation makes neither an EOS-only
rule nor a cap-acceptance rule. Both finish kinds remain unscored.

Later M1/M2 collection admission must bind actual qualified final27/540
three-chunk study checkpoints, publication/cost lineage and successful independent
raw audits to the existing final-adapter restore contract. Qualification-only
checkpoints cannot substitute. Retention enrollment, language reference/review
authority, long-context qualification, paired scoring and registered statistics
remain separate unmet requirements; hashes or fake human/fluency references
cannot satisfy them. The existing advancement thresholds and precision floors
are unchanged.

Validation: 28 CPU controls passed using tiny payloads across a full384 synthetic
roster, plus read-only frozen evidence rejection controls. Run:

```powershell
python -m unittest discover -s experiments/rineya_synth_centralized_reasoning_v1/artifacts/score_import_work -p test_score_import.py -v
```

`CPU_VALIDATION.json` records exact source/input/receipt hashes and the observed
test result. No captured response was graded; no framework, decoder, model,
GPU, teacher, training, paid service, protected bank, root-source edit, or commit
was used by this preparation.
