# Offline library evidence validator — pending producer integration

`prefix_library_evidence.validate_packet(raw, *, policy, expected_identity, selected_file_map, selected_source_map, expected_boundaries, expected_file_sha256)` parses actual bounded bytes and independently replays the externally selected plan. Every input and output has explicit CPU identity; original scope/source/context/PID-FILETIME and descriptor joins are recipe identities. The validator does not inspect current binaries or processes, qualify the observer, consume the current native journal, issue NativePASS, or establish an OS sandbox.

The required prospective packet has exact fields `schema_version`, `kind=CPU_LIBRARY_BOUNDARY_RAW_PACKET_V1`, `identity`, `policy_sha256`, `library_files`, `observations`, `producer_claims`, `fixture_only`, `native_PASS`, `native_authority_issued`, and body `sha256`. External identity contains source commit, original tensor-only scope, exact owned birth, context digest, producer source descriptor and false native authority. Policy/provider source and the whole library byte map must join independently supplied selections. `expected_boundaries` is a separately selected ordered list of `{id,parent_id,name}`; names map exactly to framework or extension create/exec transitions in policy.

Every checkpoint retains `{ordinal,time_ns,event,boundary_id,scope,snapshot,event_trace,directory_identities,cleanup}`. Population/order is initial, each real nested boundary enter/exit, precleanup, final cleanup. Snapshot and cumulative load/unload event batches use the original guard's exact raw schemas. Directory identities retain device/inode for every selected directory. Each event prefix must remain byte-value consistent, each new path/handle must match the selected prospective transition, and independently replayed state must equal every complete snapshot. Qualified lifetime conservation rejects unloads, including transient load/unload pairs. Missing/reordered boundaries, rewritten histories, unexplained libraries/handles, changed directories/clocks and incomplete cleanup fail. Incoming producer counts are retained separately from independently recomputed counts; equality is checked rather than accepted as evidence.

V1 scopes/cleanup preserve the historical CPU schema. V2 uses `OBSERVED_MANAGED_DLL_DIRECTORY_SCOPE`/`OBSERVED_MANAGED_DLL_DIRECTORY_CLEANUP`, actual managed setup/cleanup fields and `foreign_directory_registration=UNOBSERVED`; numeric substitutes for boolean fields and complete foreign-directory coverage claims fail. Its explicit CPU evidence basis remains distinct from native observations.

Limits: 16MiB raw packet;4096 libraries;65536 event rows per cumulative batch;4096 checkpoints;64 nested boundaries;600seconds recorded scope;64-bit nonnegative handles/clocks; finite numeric parser and duplicate-key rejection. The validator opens no files; selected map descriptors do not certify actual current bytes. Required source, byte, observer-losslessness, missing-event/overflow and original/preserved packet closure remain the surrounding integration's responsibility.

Reconstructing a packet from summaries cannot satisfy that obligation. Actual failure-boundary packet production/interpretation is also not implemented by this completed-conservation CPU validator.
