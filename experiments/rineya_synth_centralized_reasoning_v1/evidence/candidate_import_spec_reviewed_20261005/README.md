# Proposed final-study candidate collection/import contract

**State: specification only; native APIs, registration, implementation and authority absent.** This ignored package changes no integrated file or HEAD. No real study receipt path/hash is supplied or invented. Proposed kind/status names below are reserved design labels, not accepted current native provenance. All missing native authority slots remain explicit blockers.

The smallest useful implementation is a provenance loader plus complete-population join that emits **unscored** M1/M2 records. It must not add a grader, train, launch a worker, instantiate Torch, deserialize a checkpoint, inspect live processes/devices, open oracle labels or change any finish/statistics policy. A separately reviewed candidate collector and native auditor must first produce the genuine selected records. This spec defines the joins those future records need.

## Required authority selection

Native loading begins with an externally selected immutable `NativeCandidateSelection` file and externally supplied expected file hash plus `authority_context_sha256`. The selection binds one arm, seed101, unchanged study schedule registration, all three actual owned **study** chunk receipts/audits, final archive descriptor, candidate collector registration/auditor source, and a qualified candidate restore/collection prerequisite. Paths must be absolute regular non-reparse pointers; native slots require real typed lower-case SHA256 values and positive byte counts. Nulls, sample paths, zero hashes or a generated self-seal do not admit native records.

This is a **pre-capture** selection. Its collector registration is an independent
recipe/profile/complete-dose registration created before selection, with no
selection/candidate/config back-reference; a per-batch capture config is a later
derivative and cannot occupy that slot. After capture, a separate externally
pinned `CandidateImportSelection` selects the same pre-capture selection and
candidate identity plus all six actual batch audit/config file anchors in fixed
ordinal order. Import requires both exact externally supplied file/context pins.
The postcapture manifest belongs only to loader/output provenance; never insert
its hash or future batch audit/config hashes into the pre-capture selection,
candidate identity or frozen capture records. That would create a hash cycle.
An auditor source pin alone cannot authenticate arbitrary purported batch audits.

`PlainFileAnchor` binds raw source bytes with path/bytes/file SHA only.
`JsonDocumentAnchor` additionally states an explicit body hash convention. Sealed
documents exclude only their actual own `sha256`; unsealed documents hash their
entire parsed result, not a manufactured producer checksum. Source files have no
JSON body hash. Existing scorer/statistics source descriptors remain unchanged.

The caller must obtain the expected selection/context pins from the trusted root/reviewer scope. The loader checks those pins; it does not infer owner approval, reviewer identity or scientific authority from arbitrary JSON. A `qualified=true` field, mutual consistency or a matching count never authenticates an arbitrary self-signed audit.

The proposed external **study execution audit** uses a distinct kind/status from full27 qualification and explicitly binds the owned study authorization file. Its exact new names appear in `PROPOSED_SCHEMAS.json`; they remain unavailable until an independent owned study-audit implementation is integrated and genuinely run. The inner study protocol records retain their current closed labels. Full27 audits are admissible only as **qualification prerequisites**, never as the selected study chunk audit or final adapter.
