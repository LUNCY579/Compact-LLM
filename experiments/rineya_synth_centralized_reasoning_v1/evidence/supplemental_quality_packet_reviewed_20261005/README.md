# SYNTH readiness and measurement implementation

This is an additive, offline implementation of the accepted Rineya quality plan.
The existing SYNTH owner chat, **Build CPU-only R/S task compiler**, retains all
tracked-source, CUDA-diagnostic, native-registration and study-execution ownership.
No competing study or native worker is launched by this package. The SYNTH and
RDD worktrees and all prior evidence are preserved.

## Delivered behavior

- `readiness_packet.py` builds and independently reconstructs a byte-bound
  prospective packet from an allowlist of existing public source, approved TRAIN
  arrays and open DEV inputs. It recounts the complete 540-sequence schedules,
  27 updates, 130,562/130,574 input tokens and 5,614/5,615 target+EOS tokens.
  It validates masks/EOS, the fixed source/adapters/optimizer, the exact LR vector,
  cold start, final-only endpoint and immutable exclusive output creation.
- `measurement_enrollment.py` freezes the complete cohort and baseline plus each
  source-correct guard subset. It rejects subsequent baseline, cohort or membership
  substitution. All guard rows remain present; zero source-correct support stays
  undefined. This is computational enrollment, not native scorer admission.
- `quality_decision.py` computes exact parent-grouped R/S macro and RS gains,
  retained/damaged/rescued cases, separate formatting/abstention/capping diagnostics
  and exploratory paired-parent intervals. Its real DEV layout is 32 parents per
  skill, two conditions crossed with two renderings: 384 rows total. It requires
  both M1/M2 complete final27/540 endpoints and never lets repairs cancel damage.
- `quality_cli.py` exposes offline enrollment and decision operations. Every input
  is bounded and referenced from this external directory; outputs are exclusive.
  There is no native execution, training, confirmation or promotion command.

The new `QUALITY_SCREEN_POLICY_001.json` is the prospective **3pp, zero-new-loss
engineering screen** selected by the human. The historical SYNTH **5pp plus CI**
policy is separately pinned and unchanged. This supplement does not silently
replace a historical registration, qualify its scores or import a permit.

Every decision output remains an unqualified computational/fixture result.
Caller-provided correctness flags and completed-run dictionaries are assertions,
not proof of actual model execution or a qualified grader. Actual M0/M1/M2 native
score imports must be integrated and admitted by the SYNTH owner before native use.
The `M2_engineering_advantage_signal` and legacy `M2_advantage_claim` fields are
engineering arithmetic only; `quality_claim_permitted` remains false.

## Reproduce offline checks

Use an existing Python runtime; no dependency installation is needed. Run from
this directory with bytecode disabled and TEMP/TMP pointing to BusinessProject:

```powershell
python -B -m unittest discover -s tests -v
python -B readiness_packet.py check `
  --synth-root C:/Users/clclc/BusinessProject/ChatBubble-rineya-synth-centralized-reasoning-v1 `
  --external-root C:/Users/clclc/BusinessProject/synth-quality-readiness-20261005 `
  --output C:/Users/clclc/BusinessProject/synth-quality-readiness-20261005/READINESS_PACKET_001.json `
  --expected-sha256 f562561f4e33efe48b62f0aabc6ac117106415acf521e62183be2a1d12b133bf
```

`python -B quality_cli.py --help` documents offline enrollment/decision arguments.
Decision requires an independently selected frozen enrollment file hash and exact
baseline/cohort reconstruction. Native evidence cannot be fabricated by changing
labels, flags, paths, seeds or filenames.

All fabricated tests, temporary source mirrors, synthetic scores and derivatives
in this directory are excluded from native TRAIN/selection/DEV/confirmation.
They establish software mechanics only, never Rineya capability. No protected,
sealed, CHECK, FINAL or confirmation payload is read by the package.
