# Optional bounded library topology draft

The current library consumer expects a predeclared ordered boundary plan. No
actual Torch extension order was found in the selected observer-only evidence.
An isolated draft registers finite extension identities and bounded topology
instead: one framework root, sequential IDs, exact LIFO parents, one create/exec
pair per selected path, exec after returned create, required path completion and
closed terminal stack. The original exact DLL effect/event/snapshot replay still
checks the raw bytes after that topology validation.

Four authored controls and [independent four controls](evidence/library_boundary_grammar_reviewed_cpu_20261007/independent_review/INDEPENDENT_BOUNDARY_GRAMMAR001.json)
pass in 0.249 seconds with seven pins unchanged. Two sibling orders pass;
unknown/repeated/missing paths, wrong parents/order, open stacks, changed DLL
effects, missing events, changed snapshots and unload events refuse. The draft
does not expand the exact expected effect sets into union allowances.

[Preservation](evidence/library_boundary_grammar_reviewed_cpu_20261007/ROOT_PRESERVATION_001.json)
binds sixteen files and 213,910 bytes. Public policy/contract/auditor sources are
unchanged. No gate, permission or native event facts were supplied.

This is a reviewed rule draft, not an integrated registration. A future Torch
diagnostic must explicitly pin meaningful required extensions and exact effects;
the grammar permits an empty required set as a general schema and cannot infer
the intended dose. Current per-extension/framework effect expectations remain
unresolved. Do not label synthetic fixture topology or effects as observed native
behavior. All resource, identity, event and cleanup checks remain binding.
