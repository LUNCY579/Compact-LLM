# Ordered causal programme

1. Audit existing work and preserve historical bytes.
2. Validate new shared engineering and strictly separated track callers.
3. Generate and independently validate both fresh banks; freeze scorer, manifests,
   source and independent protocols; commit registrations before model execution.
4. Track A: qualify all five fixed arms on architecture development, then execute
   complete per-arm confirmatory shards. Aggregate only complete compatible pairs.
5. Track B: capture label-free calibration/held-out activations, compare every
   registered depth pair and bridge objective; retain shuffled/random controls.
   Freeze selection from held-out alignment alone. A failed mechanism gate closes
   downstream generation for this registered mechanism.
6. Only if Track B alignment passes, separately preregister the fixed four-dose
   architecture-development screen and candidate/control generation with the
   untouched Track B confirmatory bank. Do not tune gates on confirmation.
7. Compare frozen track conclusions only after both have conclusions. Preserve
   negative and specialized outcomes. Future mechanisms require the user's gates.

Large CPU campaigns resume by rerunning identical scheduling commands. A completed
shard is reused only under the same registration/data/config/runtime contract;
failed or interrupted attempts remain immutable and get a new execution directory.
