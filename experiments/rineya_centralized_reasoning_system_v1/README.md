## Research question

Does a verified, reusable procedure library improve long-context state tracking
beyond the same Rineya checkpoint with matched retrieval, primitive tools,
verification, and resource limits, but without reusable procedure memory?

## Smallest next implementation

Start with source-addressed evidence, explicit unknown/contradicted states, a
restricted operation executor, fresh per-question workspaces, a read-only
procedure snapshot during evaluation, and complete cost/event receipts. Qualify
these mechanics with independent CPU fixtures before proposing a native reader
screen. The design is not itself an executable harness or launch permit.

Keep one checkpoint per comparison initially. Family-role routing and
model-training experiments come later and must demonstrate their own benefit.
Hand-authored tools are infrastructure; learned or discovered procedures require
separate provenance and held-out evidence. System gains are not native-model
gains, and a clean negative is a useful research result.
