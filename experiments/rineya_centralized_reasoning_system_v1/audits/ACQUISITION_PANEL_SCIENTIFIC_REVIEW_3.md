## AP-SCI-3-001: complete count-relative shortcut survives

Coordinator `/root` noticed that every declared supported position fits
`k=min(N-2,max(1,N-4))` and placed a32/32 forecast in PLAN before the observation.

outcomes were used to choose k, and no family, slot, root, draw or order identifier
is an input to the prediction rule.

The exact decision rule is:

```text
Collect public confirmed query-entity transfers at/before the query cutoff.
Resolve active public aliases; remove actively canceled transfers.
Sort the uncanceled candidates by their public binding times; call the count N.
Evaluate only the terminal candidate's REQUIRE/EXCEPT facts at its binding cutoff.
If its state is UNKNOWN or CONTRADICTORY, return that state and null value.
Otherwise set k=min(N-2,max(1,N-4)) and evaluate only candidate k's guards.
If candidate k is SUPPORTED, return its resolved owner.
Otherwise return REFUTED/null under the complete EMPTY fallback.
```

The parser uses plain tokenized public source records, not the supplied
`public_position_controls`, constructor, core or latent oracle. Guard evaluation
retains latest eligible fact times and ties, treats REQUIRE/refuted or
EXCEPT/supported as exclusion, then contradictory, unknown and supported states
in that order. Source/query/rules are the only parser/prediction inputs. Private
gold is used after the predictions to score status and owner equality.
